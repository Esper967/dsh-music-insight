# 设计说明

## 问题

文本模型读不到音频。让它“理解音乐”有三条路：

| 路径 | 代价 | 问题 |
|---|---|---|
| 换原生音频模型 | 需要新模型、可能付费、黑盒 | 不可复现，且基准显示音乐感知仍弱 |
| 微调音频编码器 + LLM（LTU、Music Flamingo 路线） | 需要 GPU、数据、训练 | 个人项目做不动 |
| **把音频变成 LLM 可读的观察数据**（本项目） | 纯 CPU、零 API | 描述颗粒度受限于测量能力 |

本项目选第三条。核心判断：**文本模型不缺“音乐语义知识”，缺的是“能指向证据的观察数据”。**
所以项目产出不是一个“音乐理解模型”，而是一个**听感生成器**：
测量负责真，感官负责短。

## 四层架构

```
音频
 ├─ 测量层（确定性算法，可被基准检验）
 │    BPM、调性、响度曲线、频谱重心、音符密度、音级分布、结构边界
 ├─ 感官层（vibe-v2：确定性映射，把数字压成一句话）
 │    一句感受、三个情绪词、一行走向、一行手感
 ├─ 证据层（LLM 可读的序列化）
 │    panel.png + analysis.json + timeline.csv + report.md（vibe/strict）+ LIMITS.md
 └─ 解读层（模型无关，本项目不实现）
      任意 LLM 把上面几层揉成 2–4 句「像真的听过」的话
```

**分层的意义**：测量错可以查、可以改、可以上基准；措辞错只归咎于阈值表；
解读错只归咎于提示词或模型。把三者搅在一起，项目就无法证明自己「准不准」，只能靠 demo 截图。

## 为什么要有感官层

只给数字时，模型会干两件事：复述数字，或加上免责声明。实测里它写到
「112.3 BPM、平均 -20.8 dB、频谱重心 2682 Hz」就停了——因为从「-20.8 dB」
走到「雨后的薄雾」这步翻译，对模型来说没有依据，它不敢走。

三种解法：

| 方案 | 问题 |
| --- | --- |
| 在提示词里求模型「有感一点」 | 每次翻得不一样，翻错无法定位，改不动 |
| 换音频 LLM | 真的能听，但要 GPU / API，且不可复现 |
| **用代码把测量值压成措辞**（本项目的感官层） | 措辞能力受阈值表限制，但可复现、可 review、可 git diff |

选第三种。核心判断：**翻译这一步应该被固化，而不是每次现场发挥。**
`vibe.py` 只有阈值表和一个纯函数，改一句词就是改一行常量。

边界写死：感官层不新增任何音频计算，也不判断乐器 / 人声 / 流派——
证据层没有的东西，它不许有。它的输出标 `method: vibe-v2`，
用途是「让解读有个起点」，不是「代替聆听」。

## 为什么 v2 要做短

v1 的实测结果：报告信息很全（骨架表 + 手感表 + 听感锚点 + 数据表），
但模型读完之后输出的也是一大段——**输入的长度决定了输出的长度**。
用户真正的诉求是「听完什么感觉」，而不是「一份体检报告」。

所以 v2 删到只剩四个字段：

| 字段 | 内容 | 为什么留 |
| --- | --- | --- |
| `headline` | 一句感受 | 模型的第一句会照着它定调 |
| `feelings` | 三个词 | 直接给情绪词，省得模型再翻译 |
| `arc_line` | 一行走向 | 保留「哪里涨、哪里散」这一条事实 |
| `hand_line` | 一行手感 | BPM / 明暗 / 冷暖 / 密度，一行够 |

删掉的（骨架表、手感表、听感锚点）没有丢，仍然在 `analysis.json` 的 `vibe.arc`
和 `vibe.hand` 里，strict 报告也照旧。**短的是措辞，不是数据。**

## 为什么允许带数据（但不许报参数）

光有情绪会显得「像在表演听众」，完全没数据又会显得「没听过」。真实的人聊歌时是混着的：

> 副歌那下挺上头的，1 分 34 左右最满，-20 dB 那种；后面又收回去了。

所以 v2 的提示词允许、并要求**一处**具体数据：时间点、数字、调性、和弦任选其一。
边界写死：

- 最多 2 个数据点、1 个术语；
- 数据要顺口，像懂行的朋友，不能写成「根据测量 / 频谱显示 / 参数为」；
- 术语用完立刻用大白话接住（和弦说「一直绕着 C-F-G」，而不是「和声进行为 I-IV-V-vi」）。

为了让模型有东西可引，插件摘要在感受之后单独给三行：调性 / 高频和弦 / 关键时间点响度。
这三行是**素材**，不是让它抄的清单——抄清单就又回到 AI 味了。

这对「专业感」的定位很关键：**像一个懂音乐但没在写论文的人**，
而不是乐评人，也不是纯情绪输出。

## 为什么全程离线

v0.2 期间试过两条「让输出更真」的旁路，后来都拆掉了：

| 尝试 | 为什么拆 |
| --- | --- |
| 联网搜这首歌的公开评论（网易云 / 豆瓣 / 网页搜索），当改写素材 | 评论是**别人的感受**，模型会把它们揉进自己的话里，结果听起来像「一个听了很多评论的人」，不是「刚听完这首歌的人」。而且搜索引擎对脚本限流，来源还会张冠李戴 |
| 性格因子（六种人设 + 禁词 + 语气示范） | 约束越细，模型越在**表演一种语气**，而不是说自己真有的感受。多一层设定，就多一层离「原生感受」远的东西 |

结论：**感受只能来自这首歌本身**。离线不是能力妥协，是产品判断——
测量 → 一句感受这条链路越短，输出越像真的。

还有一条配套的约束：**歌名不可信**。模型看到的是文件名 / ID3 标签，可能是错的、
被改过的、同名不同曲的。如果它拿这几个字去联想歌手的八卦、歌曲的评论、歌词的意思，
那些都是**模型记忆里的互联网语料**，不是这首歌给的。

所以提示词和插件摘要里都写死了一句：

> 歌名 / 歌手只是文件标签，可能不准。不要搜索、不要调用联网工具、
> 不要引用网络上的评论 / 歌词 / 背景，只按测量转化出的感受说话。

这不是不信任模型，是不信任「标题」这个输入——**听歌的人不需要先知道歌叫什么**。

## 为什么情绪必须单列

`mood_priors` 是线性启发式，不是测量。理由：

- 小调 + 快节奏常被感知为“悲壮/热血”，不是“悲伤”
- 频谱亮可能是欢呼，也可能是失真吉他
- 情绪判断高度依赖文化、歌词、个人经历

因此代码里给它独立的字段名（`priors` 而不是 `estimate`）、显式的 `method` 和 `confidence: low`，
报告里单独一节并带 caveat。任何下游用它做情绪标注都是误用。

## 评估方案

### 测量层（可自动化）

- 数据集：自建 30~50 首，人工标 BPM / 调性 / 段落边界；或使用公开 MIR 数据集
- 指标：BPM ±2% 命中率、调性 Top-1 准确率、边界 F1（±1 秒容差）
- 回归：每个指标的基线写进 README 表格，改动必须不降级

### 解读层（需要盲评）

- 任务：同一首歌，A = 本项目底稿 + 文本模型；B = 原生音频模型直接听
- 评价：让第三方按“像不像真的听过 / 有没有事实错误 / 有没有 AI 腔”三项打分
- 关键指标：**输出里能回溯到 measurements 的比例**（可正则统计）

### 幻觉检测

strict 报告里每条结论都带 `[字段]` 引用，可自动统计引用率；
vibe 模式则检查「是否出现证据里没有的乐器 / 人声 / 年代」。

## Prior art（开工前已检索）

| 项目 | 与本项目的关系 |
|---|---|
| [MOSS-Music-Data-Pipeline](https://github.com/wx9songs/MOSS-Music-Data-Pipeline) | 做的是训练语料标注管线，产出数据不是给人/模型读的报告 |
| [review-music agent skill](https://lobehub.com/skills/grahama1970-agent-skills-review-music) | 思路最接近：MIR（madmom/essentia/librosa）→ 结构化评论。差异：它绑定单一 agent 形态与固定 taxonomy |
| [Musia](https://github.com/lachlanchen/Musia) | 本地音乐工具链封装（demucs/whisper/librosa），偏工具箱 |
| LTU / Music Flamingo / audio LLM | 另一条路线：训练音频编码器，需要 GPU 与数据 |

**结论**：MIR→评论文本这条思路不新，所以本项目的差异化落在两点：

1. **测量与措辞分层**：数字可核对、措辞可 review、可 git diff
2. **短 + 离线**：默认只给一句感受，不掺评论、不套人设，让模型说的话只来自这首歌

## 已知限制

- 没有 demucs 分离，结构与旋律分析受限（这是 roadmap 第一条）
- 和弦是“音级能量猜测”，不是和弦识别
- 中频带能量占比只是音色描述（与频谱重心相关 r=-0.89），不判断人声
- 无流派/年代/乐器识别（需要 CLAP 或标签模型）
- BPM 有倍频歧义，靠折到 70~160 缓解
- 感官层的措辞是规则，不是理解：它按阈值表说你「亮」，不是因为真的听出了亮
- 感官层的骨架靠结构段；段太少（<3）时退回 8 秒时间线，此时相位是粗粒度的

## Roadmap

3. CLAP / MERT 嵌入 → 流派与情绪标签（有监督、可评估）
