# 评估集与基线

## 语料

`纯音乐训练用/` 下有 18 首纯音乐（钢琴、弦乐、电子、动画配乐），风格以抒情/民谣为主：

| 统计项 | 值 |
|---|---|
| 可分析曲目 | 18 / 18 |
| 总时长 | 52.5 分钟 |
| BPM 范围 | 72.8 – 156.6（中位 88.5） |
| chroma 抖动（0.5s 主音级变化率） | 中位 0.518，最低 0.332，最高 0.704 |
| 调性分布 | F 大调 7、A 小调 4、其余各 1 |

## 关于调性分布的疑点

18 首里有 7 首被判为 F 大调（39%），这个比例偏高。两种可能：

1. 语料确实集中在 F 大调 / D 小调（钢琴与抒情曲常用）
2. Krumhansl 相关法在这类频谱分布上有系统性偏向

**结论：未经验证，不算基线。** 需要人工确认至少 5 首的真实调性才能判断。

### 候选间隔诊断（18 首）

把 Krumhansl 前两名候选的分数差（margin）算出来之后，情况清楚了一些：

| margin 区间 | 曲目数 | 含义 |
|---|---|---|
| < 0.05 | 3 | 基本无法区分，判谁都是掷骰子 |
| 0.05 – 0.12 | 11 | 弱优势，常见混淆对：**F 大调 ↔ A 小调**（共享 6 个音级） |
| > 0.12 | 4 | 结论相对可靠 |

例如 `Active Planets - 親愛なる世界へ`：A 小调 0.668 / D 大调 0.665，margin 0.003。

因此：

- 7 首 F 大调里绝大多数第二候选是 A 小调，**不是“偏向 F”，而是这两个调本来就分不开**
- 该修正的是**报告方式**，不是算法：输出前三个候选与 margin，低间隔直接标“不可靠”
- 真要修正算法，需要引入和弦/低音信息（根音支持哪个调），这是和弦识别之后的事

## 需要人工标注的字段

| 字段 | 用途 | 工作量 |
|---|---|---|
| 真实调性 | 检验调性估计偏差 | 每首 1 个值，5 首即可初步判断 |
| 和弦进行（至少主歌/副歌各 4 小节） | 和弦识别准确率 | 每首约 10 分钟 |
| 段落边界（时间点） | 结构检测 F1 | 每首约 5 分钟 |

## 和弦识别基准（POP909，2026-10-21）

数据：POP909 909 首中文流行（MIDI 三轨 + `chord_midi.txt` 逐段和弦真值）。
做法：`index.mid` → 合成音频（`midi_render.py`，谐波 + 指数衰减）→ `chords.detect()` → 与真值逐帧比对。

**注意**：合成音频是干净的，没有混响与踏板，准确率会偏高，只能当正确性测试。

| 版本 | 根音准确率 | 和弦准确率 |
|---|---|---|
| 初版（含解析 bug，5 首） | 50.4% | 56.4% |
| 修复和弦名解析（`C#m7` 被截成 `Cm`） | 60.6% | 51.9% |
| 参数：switch_penalty 0.5 + 时间中值平滑 5 帧（10 首） | 66.0% | 55.4% |
| **同参数，20 首** | **68.4%** | **58.2%** |

根音准确率单首区间 51%–88%。

### 无效尝试

- **低音根音加分**（bass_bonus 0.3/0.6）：根音反而降到 45%——钢琴低音常是转位或五音
- **限制 HPCP 频段**（150–2500 / 200–1500 / 250–1200 Hz）：全部低于 100–5000 Hz 基线

### 瓶颈判断

12 维音级直方图无法区分「单音」与「由泛音构成的大三和弦」：
一个 C 音的 2/3/4/5 次谐波落在 C、G、E 上，天然长得像 C 大三和弦。

要突破需要**谱峰拾取 + 谐波抑制**（判断每个峰是基频还是泛音），
或直接上训练好的和弦模型（BTC / madmom，需 torch）。

### 天花板测试（oracle 词表，20 首）

问题：如果**预先知道调性**、甚至**预先知道这首歌用了哪些和弦**，准确率能到多少？

| 变体 | 根音准确率 | 和弦准确率 |
|---|---|---|
| 基线（不限制） | 68.4% | 58.2% |
| 只允许调内和弦（调性由真值和弦反推，oracle） | 67.0% | 53.4% |
| 只允许真值里出现过的和弦（oracle 词表） | **70.8%** | **68.8%** |

### 结论：瓶颈在前端，不在解码

1. **调内约束反而更差**（-1.4 点）：说明错误不是“选了调外和弦”，而是根音本身就判错；
   而且真值里存在借用/离调和弦，限制后把正确答案排除了。
2. **oracle 词表只把根音从 68.4% 提到 70.8%**（+2.4 点），却把和弦准确率从 58.2% 提到 68.8%（+10.6 点）。
   这说明：**和弦性质与解码还能救，根音识别本身是硬瓶颈。**
3. 结论：继续在“词表/调性/解码”上做文章是死路，必须改进**音高显著性提取**（谱峰拾取 + 谐波抑制）。

### 按拍聚合（beat-synchronous，2026-10-21）

逐帧 chroma 会被琶音和经过音打散——POP909 的钢琴编曲尤其如此。改为按拍聚合，
并对**发射分数按拍标准化**（不同曲目余弦分数尺度不同，不标准化会让转移惩罚失效）。

| 变体 | 根音准确率 | 和弦准确率 |
|---|---|---|
| 逐帧（20 首） | 68.4% | 58.2% |
| **按拍（20 首，真值拍点）** | **76.4%** | 57.6% |

**根音 +8.0 点**，和弦性质几乎不变。这与前面的天花板结论一致：
瓶颈在根音/音高这一侧，拍级聚合正好补上了这一块。

⚠️ 这里的拍点来自 `beat_midi.txt`（真值）。生产环境需要自己的节拍跟踪器，
所以 76.4% 是「拍点已知」条件下的上限，不能直接对外宣称。

### 无效尝试（谐波显著性）

实现了 `salience.py`（谱峰谐波求和 + 频谱白化 + 非谐性补偿），希望通过抑制泛音
解决「单音伪装成大三和弦」：

| 变体（8 首子集） | 根音准确率 |
|---|---|
| HPCP 基线 | 64.2% |
| 谐波显著性（默认 6 谐波） | 63.2% |
| 3 谐波 / 白化 / 非谐补偿 / 不同八度衰减 | 63.1–63.9% |

**全部不优于基线。** 结论：在合成钢琴音上，泛音问题没有想象中严重；
真正的噪声来自**时间维度**（琶音），而不是音高水平维度。

### 节拍跟踪：自研 vs librosa vs 真值（20 首）

自研节拍器（`beats.py`：起音包络 + 自相关定速 + DP 定相位 + 相位微调）与 librosa 对比：

| 拍点来源 | 和弦根音准确率 | 和弦准确率 |
|---|---|---|
| 真值拍点（oracle） | 76.4% | 57.6% |
| **librosa 跟踪** | **71.8%** | **56.7%** |
| 自研跟踪 | 70.2% | 53.7% |

**真实节拍跟踪的代价约 5–6 个点。** 自研版本与 librosa 差距不大，但存在倍频错误
（如 64 BPM 判成 128）。节拍 F-measure 只有 0.21（自研）/ 0.34（librosa）——
这不是和弦识别的问题，而是 POP909 的 `beat_midi` 采用记谱拍级，
与“听感拍”常常差一个层级；和弦聚合对拍级不敏感，所以准确率只掉几个点。

### 旋律提取（严重瓶颈）

用 `melody.py`（谐波显著度 + DP 音高跟踪）在**完整混音**上提取主旋律：

| 输入 | RPA（±50 音分） | 八度容差 | 方向一致率 |
|---|---|---|---|
| 完整钢琴编曲（8 首） | **19.5%** | 46.7% | 54.3% |
| 单独 MELODY 轨（3 首） | **68–77%** | 68–77% | — |

结论：**算法本身在单声部输入上可用（约 73%），瓶颈是复调遮蔽。**
伴奏把旋律盖住后，谐波显著度无法判断哪个音是“主旋律”。

这与调性/和弦的结论不同：不是特征不够，而是**缺一个分离步骤**。
纯钢琴曲没有现成的“人声轨”可分离，demucs 也帮不上（只有 drums/bass/vocals/other）。

### 和弦性质改进：类别先验（零依赖）

问题：模板匹配会过度预测七和弦（maj7/m7），而真实语料里三和弦占 ~96%。

做法：在发射分数标准化之后，加一个按和弦性质加权的先验
（chords.QUALITY_PRIORS，来自 POP909 **第 401–500 首**的持续时间统计，
与评测用的前 20 首不相交，避免泄漏）。

| 拍点来源 | 先验前 根音/和弦 | 先验后 根音/和弦 |
|---|---|---|
| 真值拍点 | 76.4% / 57.6% | **78.6% / 77.8%** |
| librosa 拍点 | 71.8% / 56.7% | **73.8% / 73.0%** |
| 自研拍点 | 70.2% / 53.7% | **73.4% / 72.8%** |

和弦性质 **+16~20 点**，根音也顺带 +2 点（先验稳定了 Viterbi 的转移）。

注意：这是中文流行语料的先验，换到古典/爵士会偏；权重 w=0.3 是在 20 首上调的，
存在过拟合风险，需要更大评测集确认。

### 真实音乐验证（18 首，无真值 + 2 个已知答案）

用 `music-insight --chords` 在 18 首真实纯音乐上跑节拍 → 和弦 → 由和弦反推调性。

- 新旧调性（chroma 统计 vs 和弦反推）一致 **10/18**
- 和弦序列本身很合理，例如：
  - `天空の夜明け`：Am 38.5s / C 28.8s / G 28.8s → A 小调，典型 i–III–VII
  - `tears for you`：C 23.2s / G 19.3s / F 17.6s → C 大调，I–V–IV
- 两个已知答案都**只对到关系大小调层级**：
  - `終末の過ごし方より`（真值 B♭ 大调）→ 识别出 Gm 94.5s / F 67.3s / E♭ 43.3s，
    调性判成 **G 小调**（B♭ 的关系小调）——B♭ 和弦本身没被识别出来
  - `Rimelight`（听者标注 D 小调）→ 识别出 F 69.6s / Dm 43.2s / C，调性判成 **F 大调**（关系大调）

结论：**和弦反推让调性从“瞎猜”变成“关系大小调二选一”**，这是实质进步；
但要定到绝对调名，还需要区分关系大小调——最直接的信息是**结尾和弦**或**主和弦位置**。

## 大小调准确率（第二次评估，含基线，2026-10-21）

标注来源：听者凭听感填写 18 首，其中 17 首给出明确判断（#15 填“不确定”）。
两处经外部证据复核：#2 确认大调；#14 查证 tan8 钢琴谱调号 **B♭（大调）**。

| 预测方式 | 准确率 | 大调召回 | 小调召回 | 平衡准确率 |
|---|---|---|---|---|
| chroma + Krumhansl | 9/17 = 53% | 64% | 50% | 57% |
| HPCP + Krumhansl | 10/17 = 59% | 64% | 50% | 57% |
| **HPCP + Temperley** | **12/17 = 71%** | **100%** | **17%** | 58% |
| 低音根音 | 10/17 = 59% | 73% | 33% | 53% |
| 结尾三和弦 | 11/17 = 65% | 73% | 50% | **61%** |
| 多数投票 | 9/17 = 53% | - | - | - |

### 关键发现：71% 是幻觉

语料里大调 11 首、小调 6 首，**“全猜大调”就有 11/17 = 65%**。

Temperley 的 71% 只是比瞎猜基线多 1 首：它把小调召回压到 17%（6 首只认出 1 首），
本质是“倾向于输出大调”。**平衡准确率 58%，离随机（50%）只有 8 个点。**

结论：**目前所有手写调性方法都没有可用技能**，继续调 profile / 调投票权重没有意义。

### 错误类型

主要是**关系大小调混淆**：

| 曲目 | 真值 | 我们的输出 |
|---|---|---|
| #14 終末の過ごし方より | B♭ 大调（谱面） | Krumhansl → G 小调（其关系小调） |
| #17 Rimelight | D 小调（听者给出） | Krumhansl → F 大调（其关系大调） |

关系大小调共享全部音级，只靠音级统计无法区分——必须有**和弦三度**或**终止式**信息。

### 路线调整

1. **停止独立调性检测的调参**：没有真值规模，任何“改进”都无法验证
2. **调性改由和弦序列反推**：大三/小三和弦直接携带调式信息，这是正确顺序
3. 若将来需要专业级调性准确率，只能引入训练好的模型（需 torch，与 demucs 同级别依赖）

## 多源调性投票（v0.2）

从裸 chroma 相关法改成三个信息源投票：

| 信息源 | 方法 |
|---|---|
| `krumhansl` | HPCP（8192 点 FFT + 调音校正）与 Krumhansl-Kessler profile 相关 |
| `temperley` | 同一 HPCP 与 Temperley 修订 profile 相关 |
| `bass_root` | 40–250 Hz 低音能量按三和弦根音/三音/五音求和 |

18 首的结果：**三源完全一致仅 2 首，大小调一致 7 首。**

分歧主要落在关系大小调（如 `F# 小调` vs `D 大调`），这与稀疏钢琴/弦乐作品的真实和声模糊性一致，
但也说明当前三个源还不足以给出可用的调性结论。

### 过程中的一个 bug（已修）

第一版 `_rank` 只遍历了大调 profile，导致 18 首全被判成大调。修复后小调才出现（8/18）。
这个 bug 说明：**没有真值时，最危险的不是算法错，而是“错得很一致”**。

### 结论

- 调性结论目前只能作为候选，不能作为事实
- 需要外部真值：公开标注数据集，或听者的“大小调”判断（后者不需要绝对音高）
- 下一步改进方向：逐帧 key 估计 + 时间中值滤波；bass 源改用节拍对齐的根音检测
